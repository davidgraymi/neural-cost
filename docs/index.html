Find out why your model is slower than the hardware allows.

neural-cost estimates a network's useful compute and compulsory memory traffic, measures its runtime, and splits the gap to the roofline bound into physical causes. PyTorch, JAX and TensorFlow are optional adapters; the core has zero dependencies.

Explain the gap, not just its size

A 4% roofline efficiency tells you a workload is slow. It doesn't tell you why.

neural-cost goes further in three ways.

Cross-framework consistency

A PyTorch hook sees one attention op; a JAX trace sees the dot_general, exp and reduce_sum that implement it. cross_check separates granularity-invariant dense FLOPs and unique parameters, and the test suite asserts they match exactly across all three frameworks.

How it's tested

Gap attribution

attribute_gap splits measured runtime into ordered, non-overlapping components that sum exactly to the median: roofline floor, unfused traffic, lost overlap, peak derate, dispatch, kernel inefficiency, jitter and residual.

See the components

Published validation

Three predictors, none fit to the workload it predicts, scored out-of-sample on 59 workloads. The roofline is checked as a true lower bound: any measurement faster than it would falsify the model.

Gap attribution

Every millisecond, accounted for.

Calibration measures throughput as a function of size, from 32² to 4096² matmuls and from cache-resident to DRAM-sized copies, so small kernels are modeled at the rate they actually reach. On async devices only the un-hidden part of launch overhead is charged.

attribute.py
calibration = adapter.calibrate("mps")
kernels = adapter.trace_kernels(model, inputs)

attribution = attribute_gap(
    ops, measurement, hardware, calibration,
    kernel_count=len(kernels),
    isolated_seconds=adapter.replay(ops, "mps"),
    assume_fusion=False,
)
print(attribution.render())
for step in attribution.recommendations():
    print(step)
  1. 01roofline_floor

    FLOPs and fused bytes at datasheet peak with perfect overlap. Nothing can run faster.

  2. 02unfused_traffic

    Extra DRAM round-trips for intermediates a fusing compiler would keep on chip.

  3. 03serialization

    Lost compute/memory overlap: each op bounded by its own roofline.

  4. 04peak_derate

    Datasheet peak vs. measured achievable throughput at each op's size.

  5. 05dispatch

    Per-kernel launch overhead not hidden by async execution, plus per-call sync.

  6. 06kernel_inefficiency

    How much slower each op runs alone than its achievable roofline (op replay).

  7. 07timing_jitter

    Median minus fastest sample.

  8. 08residual

    Composition effects: framework glue, uncaptured ops, cache interference.

Frameworks

Bring your own framework. Or none.

The core works on portable Operation records and has no mandatory dependencies. Adapters are optional extras that emit the right operation kind for each layer.

torch

PyTorch

Eager hooks and FX tracing. Linear, Conv2d, Embedding, RNN/GRU/LSTM, MultiheadAttention, norms. Kernel tracing and op replay for attribution.

pip install "neural-cost[torch]"
jax

JAX

jaxpr tracing that recurses into jit, scan, while, cond and custom_jvp, with arbitrary dot_general contractions and NHWC convolutions.

pip install "neural-cost[jax]"
tensorflow

TensorFlow / Keras

Dense, Conv2D, Embedding, GRU/LSTM, MultiHeadAttention, BatchNormalization, LayerNormalization and pooling layers.

pip install "neural-cost[tensorflow]"

On Apple Silicon, JAX runs on the GPU through neural-cost[jax-metal] (Apple's Metal plugin) or neural-cost[jax-mps] (community plugin via MLX). Hardware is detected from a chip table, a STREAM triad, nvidia-smi, or a CPU fallback.

LLM serving models

Analytical models for modern inference.

Closed-form cost models for the techniques that dominate LLM serving, each with a gap analysis against your hardware.

Mixture-of-Experts

Top-k routing, expected loaded experts and memory thrashing at small batch.

Speculative decoding

Breakeven acceptance rate α*, including per-position acceptance profiles.

PagedAttention

Block allocation, fragmentation, prefix sharing and concurrency gain.

Continuous batching

Mixed decode and chunked-prefill iterations and optimal chunk size.

State space models

Mamba / S6 / SSD scans and linear attention.

Training memory

Parameters, gradients, optimizer state and activation bounds.

AI agent skill

Teach your coding agent to profile models.

neural-cost ships an agent skill covering when to use it, which extra to install, per-framework recipes and how to report results. It's bundled with the package, so it always matches the installed API. In Claude Code you can also add it as a plugin.

terminal
# Claude Code
neural-cost skill --install ~/.claude/skills

# Any agent that reads AGENTS.md
neural-cost skill --agents-md >> AGENTS.md
